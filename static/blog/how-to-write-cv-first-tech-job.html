How to Write a CV for Your First Tech Job

25 October 2026 · by Rayyan Khan

The first-CV problem feels circular: jobs want experience, experience needs a job. Recruiters who hire juniors know this — what they're screening for isn't a work history, it's evidence you can do the work. For a fresh graduate, that evidence is projects, and a first CV is really a well-organized portfolio of proof. Here's how to build one that survives the six-second scan.

The structure that works

1. One-line summary. "Final-year CS student; built and deployed three ML web apps; Python, FastAPI, React." Specific beats poetic — no "passionate team player" filler.

2. Skills — grouped and honest. Languages, frameworks, tools, in that order. List only what you could discuss in an interview. When we counted live tech listings, the most requested skills were testing, Python, Git, CI/CD, SQL, and Docker — if you genuinely have any of them, they belong high on this list.

3. Projects — your experience section. Two to four projects, each with: what it does, the stack, one measurable result (accuracy, users, data size, latency), and a live link. "Cotton leaf disease classifier, EfficientNet-B0, 89.7% held-out accuracy, live demo" is a complete argument in one line. A project without a link is a claim; a project with one is proof.

4. Education. Degree, university, graduation year, CGPA if it's strong. Relevant coursework only where it matches the job.

5. Links. GitHub, LinkedIn, portfolio. Recruiters click these; make sure they land somewhere real and current.

Write bullets like evidence, not duties

Compare "Responsible for data preprocessing" with "Cleaned and annotated 8,000 images in CVAT for an object-detection dataset." Duty language says what your role was; evidence language says what you did and how much of it. Every bullet should carry a verb, an object, and — wherever it's true — a number.

Mistakes that get first CVs rejected

  • Skill inflation. Twelve "expert" skills and no projects reads as fiction. Five skills with proof beats twenty without.
  • The two-page biography. One page is enough at this stage; density of proof matters, not length.
  • No links, or dead links. A GitHub profile with your project code is half your application. Test every link before sending.
  • One CV for every job. Reorder projects and skills per application so the match is visible in seconds — the matching guide covers how.
  • Design over readability. Screening software parses plain structure best. Clean, standard headings; no text baked into images.

Test your CV before the market does

Run your CV against real postings and look at the gaps with clear eyes. If your best matches all ask for one skill you lack, that's not rejection — that's your next project, assigned by the market itself. A skill gap analysis turns that list into a study plan.
